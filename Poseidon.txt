1. WHAT IS POSEIDON?
====================

Poseidon is a FOUNDATION MODEL for learning solution operators of PDEs. Rather
than training a separate model for each PDE, Poseidon is pretrained on a diverse
dataset of fluid dynamics PDEs and then finetuned on downstream tasks — much
like how LLMs are pretrained on text and finetuned for specific tasks.

The key claim: Poseidon outperforms baselines on 14 of 15 downstream tasks and
needs ~50x fewer task-specific training samples than FNO to reach the same error.


2. ARCHITECTURE: scOT (Scalable Operator Transformer)
======================================================

The backbone is called scOT. It is a hierarchical, multiscale vision transformer
arranged in a U-Net style encoder-decoder layout. The full pipeline is:

    Input function → Patch Partition → Embed → [Encoder] → [Bottleneck] → [Decoder] → Output

2.1 Patch Partitioning & Embedding
-----------------------------------
The input function (discretized on a uniform grid) is divided into small,
non-overlapping patches of size p × p. Each patch is linearly embedded into a
latent space of dimension C using a learnable matrix.

    Why patches? Same motivation as Vision Transformers (ViT) — treating the
    whole grid pointwise is too expensive for attention. Patches reduce the
    sequence length by a factor of p², making self-attention tractable.

    Fixed hyperparameter: p = 4 (patch size).

After embedding, a time-conditioned layer norm is applied (see Section 3).

2.2 Encoder (Downsampling Path)
-------------------------------
The encoder consists of L stages. At each stage:

  (a) nc SwinV2 transformer blocks process the tokens (see Section 2.4).
  (b) A patch merging operation downsamples the spatial resolution by 2× while
      doubling the channel dimension.

Patch merging works by concatenating 2×2 groups of neighboring tokens into one
token (4C channels), then linearly projecting back down to 2C channels. This
is analogous to strided convolution / pooling in CNNs.

    Fixed hyperparameters:
    - L = 4 stages
    - nc = 2 SwinV2 blocks per stage
    - Attention heads per stage: [h1, h2, h3, h4] = [3, 6, 12, 24]
    - M = 16 (window size for attention)

So at each stage the spatial resolution halves and channels double:
    Stage 1: (N/p)² tokens,  C   channels, 3 heads
    Stage 2: (N/2p)² tokens, 2C  channels, 6 heads
    Stage 3: (N/4p)² tokens, 4C  channels, 12 heads
    Stage 4: (N/8p)² tokens, 8C  channels, 24 heads

2.3 Decoder (Upsampling Path)
-----------------------------
The decoder mirrors the encoder with L stages. At each stage:

  (a) A patch expansion operation upsamples the spatial resolution by 2× while
      halving the channel dimension.
  (b) nc SwinV2 transformer blocks refine the features.

Patch expansion is the inverse of patch merging — each token is split into 4
tokens at half the channel dimension.

2.4 Skip Connections via ConvNeXt Blocks
-----------------------------------------
At each resolution level, encoder features are connected to decoder features
through ConvNeXt convolutional blocks (NOT simple concatenation like vanilla
U-Net). ConvNeXt blocks apply depthwise convolutions followed by pointwise
linear layers with GELU activation.

    Why ConvNeXt instead of simple skip connections? ConvNeXt blocks allow
    learned feature fusion between encoder and decoder representations,
    providing richer feature mixing than raw concatenation. They also add
    local inductive bias (from convolutions) that complements the attention
    mechanism's global view.

    IMPORTANT: The bottleneck (deepest level) is convolution-free — only
    attention operates there. This ensures the bottleneck captures purely
    global relationships.

2.5 SwinV2 Transformer Blocks
------------------------------
Each SwinV2 block consists of:

  (1) Time-conditioned Layer Norm (see Section 3)
  (2) Windowed Multi-Head Self-Attention (W-MSA)
  (3) Time-conditioned Layer Norm
  (4) MLP (single hidden layer, GELU activation, hidden dim = 4 × channel dim)

Attention is computed only within local windows of size M × M (M = 16),
not globally. This reduces the computational cost from O(N²) to O(N × M²).

To allow information flow between windows, consecutive transformer blocks
alternate between regular and shifted windows (the "Swin" trick). In shifted
mode, windows are displaced by M/2 in each spatial direction, so tokens that
were at window boundaries can now attend to each other.

    Why SwinV2 specifically (not original Swin)?
    SwinV2 uses cosine attention and log-spaced continuous relative position
    bias instead of the original Swin's learned relative position bias table.
    This makes the attention mechanism more transferable across different
    resolutions — critical for a foundation model that must handle varied
    grid sizes.

2.6 Positional Encoding
------------------------
Poseidon uses relative log-spaced position encodings within the SwinV2
attention mechanism. Instead of absolute positional embeddings, relative
position biases are added to the attention logits. The log-spacing ensures
that the model can generalize to resolutions not seen during training.

    Why relative instead of absolute? Absolute positional encodings tie the
    model to a specific grid size. Relative encodings encode "distance between
    tokens" rather than "position of a token", making the model resolution-
    agnostic. The log-spacing compresses large distances, preventing the
    position bias from dominating at high resolutions.

2.7 Final Output
-----------------
After the decoder, a linear projection maps from the latent dimension C back
to the output function space (number of output channels × patch size²),
producing the predicted solution.


3. TIME-CONDITIONED LAYER NORMALIZATION
========================================

This is one of Poseidon's key innovations. Standard layer norm:

    LN(v) = (v - μ) / σ

Time-conditioned layer norm modulates this with learned functions of lead time t:

    LN_{α(t), β(t)}(v) = α(t) ⊙ ((v - μ) / σ) + β(t)

where:
    α(t) = W_α · t + b_α     (learned affine function of time)
    β(t) = W_β · t + b_β     (learned affine function of time)

W_α, W_β, b_α, b_β are learnable parameters in ℝ^{C·2^i} for stage i.

    Why this design?

    (a) It enables CONTINUOUS-in-time evaluation. The model can predict the
        solution at any lead time t, not just discrete time steps. Since α(t)
        and β(t) are continuous functions, you can query any t.

    (b) It's lightweight — just 4 extra parameter vectors per layer norm,
        compared to having separate models for each time step.

    (c) The affine (linear) form was chosen for simplicity and because it
        proved sufficient. More complex time embeddings (sinusoidal, MLP-based)
        were likely tested but the linear form strikes the right balance of
        expressiveness and parameter efficiency.

    (d) It enables the all2all training strategy (see Section 4).


4. ALL2ALL TRAINING STRATEGY (SEMI-GROUP PROPERTY)
====================================================

This is the second key innovation. For time-dependent PDEs, the solution
operator S satisfies the semi-group property:

    S(t₁ + t₂) = S(t₂) ∘ S(t₁)

Meaning: evolving from time 0 to time t₁+t₂ is the same as first evolving
from 0 to t₁, then from t₁ to t₁+t₂.

Standard training: Given a trajectory with T snapshots [u₀, u₁, ..., u_T],
you train on pairs (u₀, u_k) for k=1,...,T. This gives T training pairs per
trajectory.

All2all training: You train on ALL pairs (u_i, u_j) for i < j, with lead time
t = t_j - t_i. This gives T(T-1)/2 training pairs per trajectory — a massive
increase in training data.

    For T = 11 snapshots (used in Poseidon):
    - Standard: 10 pairs per trajectory
    - All2all:  55 pairs per trajectory  (5.5× more data!)

    With 29,280 total trajectories in pretraining, this yields ~5.11M
    training examples.

    Why this works: The time-conditioned layer norm allows the same model to
    handle any lead time t, so pairs like (u₃, u₇) with lead time t=4Δt are
    valid training examples alongside (u₀, u₁) with lead time t=Δt.


5. PRETRAINING DATASET
=======================

Poseidon is pretrained on 6 operators from fluid dynamics:

5.1 Compressible Euler Equations (4 operators, 9,640 trajectories)
-------------------------------------------------------------------
The compressible Euler equations describe inviscid gas dynamics with 4 conserved
variables (in 2D): density ρ, x-momentum ρu, y-momentum ρv, and energy E.

  CE-RP:    1D Riemann problems (initial discontinuity between two constant
            states). These produce shocks, rarefaction waves, and contact
            discontinuities — the canonical test problems for hyperbolic solvers.

  CE-KH:    Kelvin-Helmholtz instability. A shear layer between two fluids
            moving in opposite directions, producing vortices and mixing.

  CE-CRP:   Curvilinear Riemann problems. Riemann problems with curved initial
            discontinuities, testing the model on non-axis-aligned shocks.

  CE-Gauss: Gaussian initial conditions. Smooth initial data that develops
            into shocks and other nonlinear wave interactions over time.

5.2 Incompressible Navier-Stokes Equations (2 operators, 19,640 trajectories)
------------------------------------------------------------------------------
  NS-Sines: Sinusoidal initial vorticity fields evolving under viscous
            dissipation and nonlinear advection.

  NS-Gauss: Gaussian vortex initial conditions.

    Why these specific PDEs?

    The authors chose them to cover diverse flow phenomena:
    - CE-RP/CRP: Sharp discontinuities (shocks, contact discontinuities)
    - CE-KH: Turbulent mixing and vortex dynamics
    - CE-Gauss: Smooth-to-shock transitions
    - NS-*: Smooth, viscous turbulence

    This diversity forces the model to learn generalizable representations
    that work across both smooth and discontinuous solutions.

Total: 77,840 trajectories × 11 time snapshots each.
With all2all: ~5.11M training examples.


6. HANDLING DIFFERENT CHANNELS AND RESOLUTIONS
===============================================

Different PDEs have different numbers of variables:
  - Compressible Euler 2D: 4 channels (ρ, ρu, ρv, E)
  - Incompressible Navier-Stokes: 1 channel (vorticity)
  - Wave equation: 1 channel
  - Poisson/Helmholtz: 1 channel

During pretraining, the maximum number of channels is fixed (nc_max). When
a PDE has fewer channels, the extra channels are zero-padded.

During finetuning on a new PDE with a different number of channels, the
embedding and output projection layers are re-initialized (since their
dimensions depend on nc), while the transformer body is kept from pretraining.
In their code, this is achieved via:

    ScOT.from_pretrained("camlab-ethz/Poseidon-<SIZE>",
                         config=model_config,
                         ignore_mismatched_sizes=True)

For different spatial resolutions, the patch-based architecture is naturally
resolution-agnostic — a 128×128 grid produces (128/4)² = 1024 tokens, while
a 256×256 grid produces 4096 tokens. The SwinV2 relative position bias
generalizes across resolutions thanks to log-spaced continuous position biases.


7. LOSS FUNCTION
=================

Poseidon is trained with the relative L² loss (also called relative MSE):

    L = || u_pred - u_true ||₂ / || u_true ||₂

This normalizes the error by the magnitude of the true solution, preventing
the loss from being dominated by regions or time steps with large solution
values. It is the standard loss in operator learning (used by FNO, DeepONet,
etc.).


8. MODEL SIZES
===============

Poseidon comes in multiple sizes:

  Poseidon-T  (Tiny):   ~7M parameters
  Poseidon-S  (Small):  ~28M parameters
  Poseidon-B  (Base):   ~109M parameters
  Poseidon-L  (Large):  ~629M parameters

The scaling shows consistent improvement with size, both for pretraining
loss and downstream task performance.


9. FINETUNING STRATEGY
========================

When finetuning on downstream tasks, only a subset of parameters are updated:
  - Embedding and output projection layers (always updated, since channel
    counts may differ)
  - Time-conditioning parameters α, β
  - Layer norm parameters
  - The attention and MLP weights in the transformer blocks can optionally
    be frozen or finetuned

This allows rapid adaptation with very few task-specific samples (often
as few as 16-64 trajectories).


10. DOWNSTREAM TASKS (15 TOTAL)
================================

In-distribution (Euler/NS with different conditions): 6 tasks
New physics (new terms added to known PDEs):          3 tasks
New time-dependent PDEs (Wave, Allen-Cahn):           3 tasks
Time-independent PDEs (Schrödinger, Poisson, Helmholtz): 3 tasks

The time-independent PDEs are handled by interpreting the steady-state
as the long-time limit of a time-dependent PDE — so the model is queried
at a large lead time t.


11. IMPLICATIONS FOR HYPERBOLIC PDEs AND SHOCKS
=================================================

11.1 What Poseidon does well
-----------------------------
- It is PRETRAINED on compressible Euler equations, which produce shocks,
  rarefaction waves, and contact discontinuities. So unlike FNO (which has
  no shock exposure during pretraining), Poseidon has seen discontinuous
  solutions.

- The multiscale U-Net architecture with skip connections can capture both
  local sharp features (via high-resolution encoder stages) and global
  solution structure (via the low-resolution bottleneck).

- SwinV2's local windowed attention avoids the global spectral bias of FNO's
  Fourier layers. It operates in physical space, not frequency space, so it
  doesn't suffer from Gibbs oscillations inherently.

11.2 Potential issues for hyperbolic PDEs
-----------------------------------------
(a) SPECTRAL BIAS FROM RELATIVE L2 LOSS:
    The relative L2 loss penalizes errors uniformly across the domain. Shocks
    occupy a small spatial region but carry critical physical information
    (entropy conditions, Rankine-Hugoniot jump conditions). The L2 loss may
    underweight shock accuracy in favor of smooth regions that dominate the
    integral. A shock-aware loss (e.g., weighted by gradient magnitude) could
    improve shock capturing.

(b) PATCH-BASED DISCRETIZATION:
    With patch size p=4, features smaller than 4 grid cells are merged into a
    single token. Thin shocks (1-2 cells wide in a high-resolution simulation)
    could be blurred by the patch embedding. This is a resolution-dependent
    issue — on coarse grids where shocks span multiple patches, this is less
    of a problem.

(c) NO EXPLICIT PHYSICS CONSTRAINTS:
    Poseidon is purely data-driven. It does not enforce conservation laws
    (mass, momentum, energy) or entropy conditions. For hyperbolic PDEs,
    weak solutions are non-unique — only entropy solutions are physically
    meaningful. Without an entropy-aware inductive bias, the model might
    learn non-physical weak solutions, especially for Riemann problems with
    multiple possible wave configurations.

(d) SMOOTH TIME CONDITIONING:
    The linear time-modulation α(t) = Wt + b assumes smooth dependence on
    lead time. But in hyperbolic PDEs, solution character can change
    discontinuously in time (e.g., shock formation from smooth data at a
    finite breaking time). A piecewise or nonlinear time conditioning might
    better capture these transitions.

(e) WINDOWED ATTENTION RANGE:
    With window size M=16, the effective receptive field per block is limited.
    While shifted windows enable global communication over multiple layers,
    shock waves propagate at finite speeds determined by eigenvalues of the
    flux Jacobian. If a shock moves faster than information propagates through
    the transformer layers, the model may lag in tracking fast-moving shocks.

(f) NO WENO/TVD-TYPE INDUCTIVE BIAS:
    Classical shock-capturing schemes (WENO, TVD, Godunov-type) use nonlinear
    limiters to prevent oscillations near discontinuities. Poseidon has no
    such mechanism — it relies entirely on learned representations. For
    out-of-distribution shock strengths or configurations, it may produce
    oscillatory predictions near discontinuities.


12. UNIQUE DESIGN CHOICES AND JUSTIFICATIONS
==============================================

(a) SwinV2 over vanilla ViT:
    Global self-attention is O(N²) in sequence length. Windowed attention
    is O(N·M²), making it scalable to large grids. SwinV2 specifically adds
    cosine attention and log-spaced relative position bias for resolution
    transfer.

(b) U-Net over plain transformer:
    The U-Net structure captures multiscale features naturally. PDEs exhibit
    phenomena at multiple spatial scales (large vortices + small shocks), and
    the hierarchical encoder-decoder explicitly models this.

(c) ConvNeXt skip connections over concatenation:
    Raw concatenation doubles the channel count and leaves fusion to
    subsequent layers. ConvNeXt blocks actively mix encoder/decoder features
    with learned convolutions, providing better feature alignment.

(d) Linear time conditioning over sinusoidal/MLP:
    Simpler, fewer parameters, and sufficient for the pretraining PDEs.
    The linearity is also interpretable — α(t) smoothly interpolates between
    short-time and long-time behavior.

(e) All2all over standard training:
    5.5× more data per trajectory with minimal additional cost (no new
    simulations needed). This is only possible because of the continuous
    time conditioning.

(f) Pretraining on ONLY fluid dynamics:
    The authors deliberately chose a SMALL set of pretraining PDEs (just 6
    operators from 2 equation families) to show that effective foundation
    models don't need thousands of PDEs — diverse physics within a small
    set is sufficient for generalization.
